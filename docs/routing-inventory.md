## Mail DNS Checklist

- Set Cloudflare proxy status to DNS-only for `mail.facilities-engineering.com`.
- Create `A` and/or `AAAA` records for `mail` to the public mail server, or a DNS-only `CNAME` if the mail provider supports it.
- Create `MX` for `facilities-engineering.com` pointing to `mail.facilities-engineering.com`.
- Publish SPF as a TXT record allowing the mail host or outbound relay.
- Publish DKIM TXT records generated by Mail.
- Publish DMARC TXT record, starting with monitoring before enforcing quarantine or reject.
- Set PTR/reverse DNS for the mail server public IP to `mail.facilities-engineering.com`.
- Confirm outbound TCP/25 is allowed, or configure an authenticated SMTP relay.
- Install and renew TLS certificates for SMTP submission, IMAP, and any Mail web/admin UI.

## Scaling Guidance

- Prefer Cloudflare Tunnel, Tailscale/WireGuard, or one central reverse proxy for future self-hosted computers.
- Avoid exposing random high ports publicly. Publish stable hostnames and route internally.
- Keep databases, object storage admin ports, Redis, MQTT internals, and management dashboards private unless explicitly reviewed.
- Route by hostname and service name, not by private IP in frontend links.
- Put one reverse proxy, tunnel connector, or service discovery entry in front of each new host so applications can move without changing user-facing URLs.
- Use Facilities ES labels in public docs and screens: Assets, Projects, Systems, Analytics, Alarms, Wireless, Mail, Johny, and Administration.
